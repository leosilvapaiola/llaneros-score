=====================================================================
ORIGINAL REQUEST
=====================================================================
User wants a scorekeeping web app for their softball team, to be used
by fans/volunteers seated on the sidelines. Requirements:
- Not overly "graphical" / no tablet-only fancy software.
- Load up the team's own roster only (not the rival roster, for now).
- Track offensive at-bats and base running so that if a scorekeeper
  makes a mistake, the inning can be reconstructed.
- UI should use combo boxes plus an interactive diamond-shaped
  dashboard for inputs.
- Hosting: static site on GitHub Pages (personal account).
- Backend idea floated: personal AWS account, aiming for free-tier
  serverless resources, but this was NOT required for the MVP.

=====================================================================
DECISIONS / RECOMMENDATION GIVEN
=====================================================================
- Built a pure HTML/CSS/vanilla-JS app (no framework, no build step)
  so it can be dropped straight into GitHub Pages.
- All state persisted in browser localStorage; JSON export/import
  provided for backup/sharing between devices (no backend needed for
  a single device scoring one game at a time).
- Documented an optional future AWS serverless path (API Gateway +
  Lambda + DynamoDB, maybe WebSocket API for live sync) in README.md,
  to be added later only if multi-device live sync becomes necessary.
  Not implemented yet - just documented as a recommendation.
- Data model simplification: the app only tracks OUR team's batting
  (single continuous lineup, cycling batting index, inning counter
  that increments after 3 outs). It does NOT model the opposing
  team's lineup/defense - that was an explicit scope decision based
  on the user's request ("track our offensive at-bats").

=====================================================================
FILES CREATED (all under anotacion-softball-app/)
=====================================================================
- index.html
    Tabs: Roster | Partido (Game) | Bitacora (Log) | Datos (Data).
    Roster tab: add/remove players (number, name, position).
    Game tab: opponent/date + build batting lineup (reorder with
      up/down buttons) -> Start game -> scoreboard (inning, outs,
      runs, current batter) + diamond SVG + play form.
    Log tab: full play-by-play table (inning, batter, result, runs,
      outs, bases before/after) for reconstructing any inning.
    Data tab: export JSON, import JSON, reset all data.

- css/style.css
    Mobile-first, simple styling, no external UI framework/CDN.

- js/store.js
    All state + localStorage persistence (key: softball-app-state-v1).
    Exports: getRoster, addPlayer, removePlayer, getGame, startGame,
    endGame, currentBatterId/Name, recordPlay(result, destinations),
    undoLast, endInningManually, exportJSON, importJSON, resetAll.
    recordPlay() takes a result code (1B/2B/3B/HR/BB/HBP/K/GO/FO/LO/
    FC/E/SF/SB/DP) plus a destinations map for batter + any occupied
    bases (out/stay/1B/2B/3B/home) - this manual-override design is
    what makes exact reconstruction possible even for weird plays.
    undoLast() restores the previous bases/outs/runs/battingIndex
    from the popped log entry's stored "before" snapshot.

- js/diamond.js
    renderDiamond(svgEl, bases, roster) - draws an SVG diamond with
    diamond-shaped bases at 1B/2B/3B, highlighting occupied bases
    with the runner's jersey number.

- js/app.js
    Glue code: tab switching, roster form/list rendering, lineup
    builder (reorderable), game board refresh, dynamic runner-control
    combo boxes built from DEFAULTS per result code (auto-prefill,
    fully overridable), play form submit -> store.recordPlay, undo
    button, end-inning button, log rendering, export/import/reset
    wiring, init on load (resumes an in-progress game from
    localStorage if present).

- README.md
    Usage instructions (in Spanish, matching user's language), GitHub
    Pages deploy steps (git init/add/commit/push + enable Pages on
    main branch root), and the AWS serverless upgrade path notes
    described above.
